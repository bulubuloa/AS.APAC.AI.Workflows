Part 1 of AI in the Development Workflow. Last updated 21 Sep 2026.

Goal of this page: after following it, claude mcp list shows Jira/Confluence and Playwright connected, the agent can read an ABE ticket by key, and the permission model is set so reads are silent and writes always ask.

1. What MCP is, in one paragraph

MCP (Model Context Protocol) is the plug standard that lets an AI agent call external systems as tools. An MCP server exposes a set of named functions (e.g. getJiraIssue, searchConfluenceUsingCql, browser_click); the agent's client (Claude Code) lists them, decides when to call them, and shows you each call. The server runs either as a local process on your laptop (Playwright) or as a hosted HTTPS endpoint you authenticate to with OAuth (Atlassian). Nothing is shared between developers — each of us connects with our own account and the agent only sees what we can see.

Databases, AWS (CloudWatch Logs, Parameter Store, CodePipeline) and Kontent are not MCP servers — the agent reaches them through ordinary CLI tools (sqlcmd, mysql, aws, curl) that are allow-listed in the permission settings (§5). That is deliberate: a CLI over an SSH tunnel is easier to audit and to restrict to read-only than a database MCP, and the AWS CLI already carries the SSO profile.

RSA, Benefit and Vendor do not use Sentry. Production errors live in CloudWatch Logs (application log groups and the MobileRoadsideLogProxy Lambda for the mobile app); the agent reads them with aws logs filter-log-events / aws logs start-query (Logs Insights). If a Sentry MCP shows up in claude mcp list on someone's laptop it is from another client's project and is not part of this workflow.

3. Install and connect

3.1 Prerequisites

  • Claude Code ≥ 2.1 (claude --version), Node 20+ (for Playwright's npx).
  • Your @internationalsos.com / Aspire Atlassian account with access to the ABE project and the AD space.
  • TWG CLI installed at ~/.local/bin/twg (add to PATH).

3.2 Add the servers (user scope, once per laptop)

# Jira + Confluence — name it after the site so several Atlassian tenants can coexist
claude mcp add --transport http -s user atlassian-isos https://mcp.atlassian.com/v1/mcp

# Playwright (local browser)
claude mcp add -s user playwright -- npx -y @playwright/mcp@latest

# Check
claude mcp list

-s user stores the entry in ~/.claude.json so it is available in every repo. Omit it to scope a server to one project (written to .claude.json under that project); use .mcp.json in the repo root only for servers the whole team should share via git — never for anything carrying a token.

3.3 Authenticate

  1. Start claude in any repo and type /mcp.
  2. Select atlassian-isos → Authenticate. A browser opens on id.atlassian.com; approve for the internationalsos site.
  3. Back in the terminal the server shows connected. Playwright needs no auth; it downloads Chromium on first use.

If you also work on another Atlassian tenant, add it as a second server with a different name (atlassian-omnicasa in our setup). Each server keeps its own OAuth token and its own tool prefix, so the agent can never confuse the two sites.

3.4 Smoke test

In a Claude session:

Read ABE-5457 and tell me its status, assignee and the last comment.

Expected: one call to mcp__atlassian-isos__getJiraIssue, then a plain answer. If the agent says the tool is unavailable, run /mcp and check the server state; if it gets a 401, re-authenticate.

4. How tools appear to the agent

Every MCP tool is named mcp__<server>__<tool>, e.g. mcp__atlassian-isos__searchJiraIssuesUsingJql or mcp__playwright__browser_snapshot. Claude Code keeps most of them deferred — only the name is loaded until the agent needs the schema — so having 150 tools connected does not cost context. You can see the full list with /mcp → server → Tools.

The tools we lean on most:

ToolPurpose
getJiraIssueFull issue by key: summary, description (ADF/markdown), status, priority, labels, fix versions, parent, sub-tasks, issue links, comments.
searchJiraIssuesUsingJql"All open ABE bugs touching RSA", "tickets in fixVersion 28Aug2026".
getJiraIssueRemoteIssueLinksConfluence pages / external links attached to the issue.
addCommentToJiraIssuePost the analysis, a question to the BA, or the QA hand-off with @-mentions (lookupJiraAccountId for the ids). Permission-prompted.
twg jira workitem transition (CLI)Move status (permission-prompted; we usually leave this to the human).
getConfluencePage, searchConfluenceUsingCqlRead specs, runbooks, release notes referenced by the ticket.
browser_navigate / _snapshot / _click / _take_screenshotPlaywright: reproduce and verify in a real browser.
aws logs filter-log-events, aws logs start-query (CLI, not MCP)CloudWatch: find the exception behind a vague bug report; Logs Insights for counts over time.

5. Permissions — reads silent, writes ask

Claude Code asks before every tool call unless the call matches an allow rule. We allow-list read-only tools and CLI commands so the agent can investigate without interrupting, and leave every write prompted. Project-level rules live in .claude/settings.json (committed) and .claude/settings.local.json (personal, git-ignored).

{
  "permissions": {
    "allow": [
      "mcp__atlassian-isos__getJiraIssue",
      "mcp__atlassian-isos__searchJiraIssuesUsingJql",
      "mcp__atlassian-isos__getJiraIssueRemoteIssueLinks",
      "mcp__atlassian-isos__getConfluencePage",
      "mcp__atlassian-isos__searchConfluenceUsingCql",
      "mcp__playwright__browser_snapshot",
      "mcp__playwright__browser_take_screenshot",
      "Bash(git log:*)", "Bash(git diff:*)", "Bash(git status:*)",
      "Bash(sqlcmd:*)", "Bash(/opt/homebrew/opt/mysql-client/bin/mysql:*)",
      "Bash(aws secretsmanager get-secret-value:*)",
      "Bash(aws logs filter-log-events:*)", "Bash(aws logs start-query:*)", "Bash(aws logs get-query-results:*)",
      "Bash(aws ssm get-parameter:*)",
      "Bash(ssh:*)"
    ],
    "deny": [
      "Bash(git push --force:*)",
      "Bash(rm -rf:*)"
    ]
  }
}
  • addCommentToJiraIssue, transitionJiraIssue, every twg … create/update, git push and any SQL that is not a SELECT stay unlisted → prompted.
  • sqlcmd/mysql being allowed does not make writes silent by itself — we pair it with read-only DB logins (UAT) or explicit "SELECT only" instructions in the repo CLAUDE.md for prod. The tunnel user for prod has no write grants.
  • Run /permissions inside a session to see what is currently allowed and where each rule comes from.

7. Security notes

  • OAuth tokens are stored in the OS keychain by Claude Code; app passwords for Bitbucket live in git's credential helper. Neither should ever be pasted into a prompt or a settings file.
  • The agent sends tool results to the model. Do not point it at production PII tables unless the ticket requires it, and prefer aggregate queries (COUNT, GROUP BY) over row dumps.
  • Everything the agent posts to Jira/Confluence is attributed to you. Read it first.
