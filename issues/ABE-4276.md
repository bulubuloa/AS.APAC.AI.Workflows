📝 Acceptance Criteria – Session Timeout
1. Session Timeout
User session automatically signs out after 30 minutes of inactivity.
At 25 minutes of inactivity, the system displays a prompt message asking the user if they want to extend the session.
image-20251212-064309.png
If the user selects Yes, the session is extended by another 30 minutes.
If the user selects No or does not respond, the session expires at the 30-minute mark.
After timeout, the user is redirected to the login page.
2. General Behavior
Session timeout and JWT expiry are synchronized (both expire at 30 minutes unless extended).
No discrepancies between UI session state and backend token state.
Security is maintained: expired sessions/tokens cannot bypass authentication.
User experience is smooth: prompt appears consistently at 25 minutes, and extension works without errors.
IN SIT + UAT: 3 mins display popup, 5 mins time out
