- **RSA job → Benefit customer link is `customer_redeemed_privileges.RoadSideJobId`** → `.CustomerId` → `customers.CustomerAttributes` (JSON keyed by FieldCode); tier via `.ProgramCustomerTierId` → `programscustomertiers.Name` (localized JSON `{"en":...}`), NOT `client_customer_tiers` directly. 367 of 4505 rows carry a RoadSideJobId.
- **B1 RESOLVED (code)**: new endpoint `POST api/webhook-roadside/customerredeemedprivilege/porsche-report-data` on branch `jira/ABE-5368-porsche-report-data` in ABCB.Clone (off `roadside-sync-data-sit`), commits 24e4f15b3 + 9b8b0c971. Returns **200 + empty array**, never 404 — the neighbouring `query-by-roadside-job-ids` 404s on no-match and that would break the header-only-workbook AC. 500 ids/statement, sequential chunks, 20k cap, ReadUncommitted, `X-Query-Ms` header.
- **B2/B3 RESOLVED from prod (Benefit `clients.Id` 115, ClientIdExternal 1962)**: prod PTH has all six attributes plus `CarModel`, all mandatory; all 59 PTH customers populated. **The field code is `Btype`, not `BType` as the Jira dictionary says** — lookup must be case-insensitive. Tiers are **New Vehicle / Non Member / Pre-Owned** (program "Porsche RSA"); the template's "Used 1 Year" sample is junk. Report Type = raw tier name, no mapping.
- **Dates are stored as `DD/MM/YYYY` strings** in CustomerAttributes (e.g. "24/08/2026") — the dictionary note was right, the template's `20250625` / `2020-12-12 00:00:00` samples were wrong. Pass through untouched.
- **Seeded 2026-09-08** (script `WebHookSyncDataRsaBenefit/SqlScript/ABE-5368_sit_test_data.sql`, applied): 7 field configs on SIT client 678 + UAT client 555, attributes on SIT customer 1099120 and UAT customers 4521679 / 4521709. DataTypeId is 50593 TEXT / 50594 NUMBER / 50595 DATE on **both** SIT and UAT (prod uses 50263/50264/50265).
- **UAT `client_customer_field_config` has no `IsReadOnly` column** — SIT and prod do. Any insert script must branch on this.
- **SIT has NO index on `RoadSideJobId` at all**; prod has `RoadSideJobId_UNIQUE`. So the endpoint table-scans on SIT and SIT timings do not predict prod; it also can't be made UNIQUE while SIT holds 283 rows with `RoadSideJobId = ''`. The endpoint carries a `seenJobIds` guard because of this.
