## Context

As a Finance Report User, I want to view and search Payment Report records using Job ID, so that I can easily identify and reconcile payments associated with RSA fulfillment redemptions.

### 1. Payment Report Enhancement – Job ID Display

**Updated Logic**
- Display a new column named **Job ID** in the Payment Report detail listing.
- The **Job ID** column will be positioned immediately to the right of the **Case ID Number** column.
- The new column shall be displayed in both: Payment Report detail screen (Report Details tab) and the downloaded Excel report.

**Data Source & Display Behavior**
- The system shall retrieve the **Job ID associated with the redemption record** — through the existing redemption-to-job relationship.
- Job ID shall only be populated when all of: the redemption belongs to a Privilege configured with **Redemption Mode = Fulfillment**; the redemption was fulfilled through the **RSA Platform**; a Job record exists and is linked to the redemption.
- If no eligible Job ID exists, the column stays blank.
- The Job ID on-screen shall match the Job ID exported to Excel AND the Job ID in the View Redemption popup.

### 2. Payment Report Filter – Job ID Search

- New filter field **Job ID**, positioned **between Case Number and Payment Mode**. Default blank; blank returns all records.
- Partial text matching, case-insensitive; complete or partial value.
- Examples: `12345` → JOB12345, 12345A · `RSA` → RSA0001, RSA0002 · `001` → JOB001, RSA001A
- Leading/trailing spaces trimmed before search; empty input is not a validation error.

### 3. Excel Export Consistency

- Exported report includes Job ID in the same relative position: **Case ID Number → Job ID → First Name**.
- Records with Job IDs export the exact value; records without contain an empty cell.
- Existing export formats, formulas, file naming and download behaviour unchanged.

## Goal

Finance users can see and filter the Payment Report by the RSA Job ID of fulfilment redemptions, on screen and in the Excel export, with the same value the View Redemption popup already shows.

## Requirements

1. Add `Job ID` column to the Payment Report detail grid, right of `Case ID Number`.
2. Add `Job ID` column to the Excel export at the same position (Case ID Number → Job ID → First Name).
3. Populate Job ID from the redemption→job link only for Fulfillment-mode privileges fulfilled via the RSA platform; otherwise blank.
4. Add `Job ID` filter between Case Number and Payment Mode; blank = no filtering.
5. Filter: case-insensitive `contains`, input trimmed, no validation error on empty.
6. Value must equal what the View Redemption popup shows (reuse its source). (inferred: same field, not a re-derivation)

## Analysis
Verified 2026-09-21 against UAT (BenefitPreProdV3 via tunnel, read-only) and PROD (Aspire, SELECT-only). Code = ABCB `develop` (1371c159f) for the API, ABF `main` for the UI.

### Understanding
- "Payment Report → Report Details tab" = ABF `Pages/Reports/Finance/FinanceBreakdownReport.razor` (report name `FinancePayment`), fed by `GET api/clients/report/get-detailed-payment-report` → `ReportService.GetDetailedFinanceReport` → stored procedure `Benefit_SP_GenerateDetailedFinanceReport` (MySQL). Excel/CSV/Text come from the same SP via `GET …/export-finance-breakdown-report` (`ExportExcelFinanceBreakdownReport`, `FinanceBreakDownStringBuild`).
- The View Redemption popup (`Shared/Dialogs/CustomerRedemptionDetail.razor:133`) shows `detail.roadSideResponse.JobId`, which the API fills from `customer_redeemed_privileges.RoadSideJobId` (`CustomerPrivilegeInventoryService.cs:965`). That column is the single source; "Job ID" = the RSA job number (`26JBxxxxxx`).
- "Redemption Mode = Fulfillment" = `privileges.IsSpecificBookingRequired` (`PrivilegeV3Service.cs:185` maps it as `RedemptionModeIsFullfillment`). "Fulfilled through the RSA platform" has no column of its own: `RoadSideJobId` is only ever written by the RSA redemption endpoints (`PrivilegeService.cs:4380`, `:5153`, `:12019`), so a non-null value *is* the RSA-platform marker.

### Root cause / design
Add the value at the source and carry it through unchanged:
1. **SP** — join `privileges pv ON pv.Id = crp.PrivilegeId`; select `CASE WHEN pv.IsSpecificBookingRequired = 1 THEN crp.RoadSideJobId END AS JobId`; new last parameter `IN jobId NVARCHAR(200)`; filter `(jobId IS NULL OR jobId = '' OR (pv.IsSpecificBookingRequired = 1 AND crp.RoadSideJobId LIKE CONCAT('%', jobId, '%')))`. LIKE on a `general_ci` column gives the case-insensitive partial match the ticket asks for.
2. **API** — `PaymentReportRequest.JobId` (trimmed → null in `NormalizePaymentReportRequest`), `@jobId` parameter, `BreakdownFinanceReportResponse.JobId`, Excel mapper inserted after CaseNumber, text/CSV header + row.
3. **ABF** — `PaymentReportRequest.JobId`, `&jobId=` on both endpoints, filter field between Case Number and Payment Mode, `<MudTh>`/`<MudTd>` after Case Id Number.
