4. Install the kit

./ai-workspace/bootstrap.sh

What it does, so nothing is a surprise: copies the global ~/.claude/CLAUDE.md; puts CLAUDE.md, .claude/commands/ and .claude/settings.json in the workspace; a CLAUDE.md in each repo; symlinks ~/.claude/projects/<slug>/memory for the workspace, ABCB, ABCB.Clone and ABMB into ai-workspace/memory/ (existing local notes are merged in, the old folder is kept as memory.bak-…); symlinks issues/; registers the MCP servers; installs the secret guard as a pre-commit hook. Re-running it is safe.

5. Authenticate

  1. Claude Code: claude in the workspace → sign in with the company account when prompted → /mcp → atlassian-isos → Authenticate → approve for the internationalsos site. The server shows connected. Playwright needs no login (downloads Chromium on first use).

  2. twg: run twg confluence space get AD — the first call opens the Atlassian OAuth page; approve for the same site.

  3. AWS: aws configure (or SSO) for ap-southeast-1; aws sts get-caller-identity must print account 739075353953.

  4. Bitbucket: create an app password (repo read/write), let the first git push store it in the macOS keychain. The agent's shell will usually still be refused — you push, it prepares.

  5. Confluence attachments (only if you will publish diagrams): personal API token from id.atlassian.com, saved with pbpaste > ~/.config/atlassian/token; chmod 600 ~/.config/atlassian/token.

8. First ticket — prove the loop works

The kit installs six slash commands — the whole loop, each appending its section to issues/ABE-xxxx.md:

Command

Does

Never does

/task-fetch ABE-xxxx

Jira → issues/ABE-xxxx.md (brief, requirements, AC, comments, links)

read code, analyse

/task-analyse issues/ABE-xxxx.md

code touchpoints with file:line, facts measured on SIT/UAT/PROD, root cause or design, blast radius, questions, plan

write anything but the task file

/task-implement issues/ABE-xxxx.md [--auto]

/task-verify issues/ABE-xxxx.md

evidence per acceptance criterion: Playwright on SIT/UAT, before/after DB counts, logs; ticks the AC

/task-deliver issues/ABE-xxxx.md

rebase check, PR text per repo, QA comment draft (posted only on your yes), release lines, human-steps list, memory notes

push, merge, transition, deploy

/task-run ABE-xxxx [--cowork | --auto]

all five in sequence; pauses after fetch and after analysis (default), also before every commit and before posting (--cowork), or not at all (--auto — never for prod-data or payment logic)

skip a step's rules

cd ~/Projects/OmnicasaAS
claude
> /task-run ABE-xxxx        # or step by step: /task-fetch → /task-analyse → /task-implement → /task-verify → /task-deliver

What to expect on the first run: the agent reads the workspace and repo CLAUDE.md, the memory index, and asks for permission on anything outside the allow list (comments, pushes, SQL writes). If it asks for something that is clearly read-only and repetitive, add it to .claude/settings.local.json — that file is yours and stays out of the kit.

9. When you finish a ticket

  1. Ask the agent: "save what you learned to memory" — new or corrected notes appear under ai-workspace/memory/.

  2. cd ai-workspace && git add -A && git commit -m "ABE-xxxx notes" && git push — the pre-commit guard blocks anything that looks like a credential.

  3. The task file in issues/ travels with it; the next person (or agent) starts from the file, not from zero.

10. Troubleshooting the usual suspects

  • "Access denied: write_confluence" from the MCP — expected; the agent uses twg for Confluence writes. Jira comments through the MCP do work.

  • Empty diagram boxes on Confluence — the Mermaid/draw.io apps only render macros created in their editor; the kit's generators attach PNGs instead (confluence/data-processors/README.md).

  • "Authentication failed for bitbucket.org" from the agent — expected; run the push yourself with ! git push … in the prompt.

  • Long commands wrap in the prompt and split — keep one-liners short or put them in a script the agent writes for you.

  • Auto-mode classifier refuses an action (secret-store writes, IAM, prod PII copies) — by design; the agent hands you the script.

  • Preprod jobs fail on MySQL connect — the preprod Aurora cluster is stopped; develop and test on SIT/UAT.
