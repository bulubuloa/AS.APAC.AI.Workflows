# apac_mobile_roadside (ABMR) — RSA provider mobile app "Aspire Partner" (Android)

- Source: `src/` (Gradle 8.13, AGP 8.13, Kotlin 2.0, compileSdk 36, minSdk 26). Single module `app`, package `com.aspire.partner`: Jetpack Compose + Material3, Hilt DI, Retrofit/Gson, Room, DataStore, Firebase (Crashlytics, Analytics, App Distribution), Google Maps/Location, AWS CloudWatch Logs SDK. `legacy/` is the pre-2025 Java/Gradle app — read-only history, do not build or edit.
- Layout (`src/app/src/main/java/com/aspire/partner/`): `service/network/*` Retrofit interfaces per feature (auth, job, jobphoto, vehicle, announcement, devstatus, force, logProxy) + `BkkRsaPartnerClient`; `usecases/*uc` business flows; `views/<screen>` Compose screens (login, otp, dashboard, jobdetail, jobhistory, jobphoto, map, vehicle, announcements, notifications, settings, policy); `core/` Abstract{Activity,ViewModel}; `RoadsideApp.kt` application.
- Backend: every call goes to ABMB `BkkRsaPartner` (`RoadSide/bkkrsa2020-master/BkkRsaPartner/Api/PmwsController*.cs`, routes `api/pmws/*`: `login`, `refreshtoken`, `job/{id}`, `whenonjob/{jobId}`, `whenready`, `syncjob`, `jobphoto/{id}`, `vehlst`/`vehinfo`/`bindvehdev`/`confirmvehdev`, `devstatus`, `announcements`, `mobile-force-update`). Change the contract on both sides in the same ticket; the RSA side deploys per env branch (see ABMB `CLAUDE.md`), the app per flavour.
- **One branch, four flavours.** Work happens on `main` (`development` is 87 commits behind and dead; feature branches `jira/ABE-xxxx`). Env is a Gradle product flavour in `src/app/build.gradle.kts`: `sit` → `partner-roadside-sit.aspireasia.net`, `uat` → `partner-roadside-uat.aspireasia.net`, `prerpod` (sic, typo is the flavour name) → `test.aspirerasservice.com`, `prod` → `partner.aspirerasservice.com`. Each flavour has its own applicationId suffix, versionName and Firebase app id — bump the flavour's `versionName` when releasing; `versionCode` = `CODEBUILD_BUILD_NUMBER` + per-flavour offset.
- Build/deploy: `buildspec.yml` (sit) / `buildspec-uat.yml` / `buildspec-prod.yml` run `./gradlew assemble<Flavour>Release` then `appDistributionUpload<Flavour>Release` (Firebase App Distribution, tester list in build.gradle.kts) and rename the APK `<applicationId>.<versionName>.<build>.apk`. The CodeBuild projects were not found in account 739075353953 ap-southeast-1/us-east-1 (checked 22 Sep 2026) — ask Vimukthi where they live before assuming a push deploys. Prod = Play Store listing `com.aspire.partner`, distributed via Firebase then store.
- Local build: needs JDK 17 (AGP 8.13) and Android SDK 36 (`src/local.properties` `sdk.dir`, git-ignored). `cd src && ./gradlew assembleSitDebug` for a device build; `./gradlew testSitDebugUnitTest` for JVM tests; `connectedSitDebugAndroidTest` needs an emulator. Signing config points at `app/sec/keystore_dev.jks` with defaults from env vars — the release keystore, `sec/*.json` Firebase credentials and `google-services.json` are **committed in the repo**: never paste their contents anywhere, never rotate them without the team.
- Tests today: `ExampleUnitTest`, `ExampleInstrumentedTest`, `views/announcements/AnnouncementCardTest` (Compose UI test) — there is no real unit coverage; QA is manual on the SIT/UAT flavour APKs. This is the "native RSA mobile app" whose automation framework decision is a Vietnam 2026 workshop output (Hoang + Vimukthi).
- Localisation: `res/values` (en), `values-en-rUS`, `values-vi`, `values-ko`, `values-ms` — add strings to all five. Logs go to CloudWatch `/aws/lambda/MobileRoadsideLogProxy-{sit,uat,dev,prod}` via `LogProxyAwsClient` (`LOG_URL` API Gateway `dvvziypgph`).
- Test accounts: provider logins live in RSA `cloud.UserAccount` with `isProviderMobile = 1` (see memory `abe-5457-provider-mobile-flag`); OTP delivery is the flaky part of any automated login — plan around it.
