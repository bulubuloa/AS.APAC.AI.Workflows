Part 0 of AI in the Development Workflow. Last updated 21 Sep 2026.

Goal of this page: a new developer clones the product repos and one small repo — ai-workspace — runs one script, authenticates three things, and their agent starts with the same instructions, commands, permissions, access recipes and memory as the person who worked on the projects before. Nothing lives only on one laptop any more.

1. The problem this solves

Until now the "setup" was spread across one machine: a global ~/.claude/CLAUDE.md, slash commands in two places, a 528-rule local allowlist, MCP registrations in ~/.claude.json, and — the part that actually makes the agent fast — about 50 memory notes under ~/.claude/projects/<path>/memory/ holding environment ids, drifted stored procedures, pipeline quirks and incident notes. The Sprint 70 example shows what those notes are worth (48 minutes instead of a day). They were not shared with anyone, not versioned, and one of them contained a database password.

3. Take over in 15 minutes

Full step-by-step with prerequisites, accounts to request, tunnel ports and troubleshooting: Setup guide — new machine, step by step. Repository: github.com/bulubuloa/AS.APAC.AI.Workflows.

mkdir -p ~/Projects/AspireDigital && cd ~/Projects/AspireDigital
git clone …/apac-booking-modernization-backend.git ABMB
git clone …/apac-benefit-vendor-backend.git        ABVB
git clone …/apac-benefits-frontend.git             ABF
git clone …/apac-benefit-client-backend.git        ABCB          # data-processer-* branches
git clone …/apac-benefit-client-backend.git        ABCB.Clone    # develop (ClientService.API)

./ai-workspace/bootstrap.sh      # instructions, commands, settings, memory links, MCP servers, secret guard
claude                           # /mcp → atlassian-isos → Authenticate
twg                              # OAuth on first run
aws sso login                    # account 739075353953, ap-southeast-1
# open the DB tunnels (ports in access/ACCESS.md)
./ai-workspace/doctor.sh         # one line per check

The folder names matter: the memory notes and the workspace instructions refer to repos by these names, and Claude Code keys memory by the absolute path, which bootstrap.sh computes for whatever path you cloned to.

doctor.sh output on the reference machine, 21 Sep 2026: every check green except the RSA prod tunnel, which was simply not open.

4. How memory stays shared

  • Claude Code writes memory notes to ~/.claude/projects/<slug>/memory/. The kit makes that directory a symlink into the repo, so a note written at the end of a ticket is a file in ai-workspace/memory/ waiting to be committed. The workspace CLAUDE.md tells the agent to do exactly that at the end of each ticket.

  • The human reviews the memory diff like any other diff. Wrong facts are corrected or deleted, not left to mislead the next session.

  • A pre-commit guard (claude/secret-guard.pl) refuses Atlassian tokens, AWS keys, JWTs and password values. Building the kit found one real password in an old note; it is now a pointer to the secret's name.

  • Two developers on the same ticket share notes through git the same way they share code. Conflicts are rare because notes are one fact per file.

6. Keeping the kit honest

  1. A fact changes (a pipeline, a branch, an environment id) → fix it in workspace/ or memory/, commit, push. The Confluence pages that quote it are regenerated from confluence/ when they are the generated ones, or edited when they are prose.

  2. A new repo joins the workspace → add workspace/repos/<NAME>/CLAUDE.md and a memory folder; bootstrap.sh picks both up.

  3. A command proves useful across tickets → it goes into claude/commands/, not into one person's ~/.claude.

  4. doctor.sh is the first thing to run when "the agent can't see X" — it says which of the tools, links, MCP servers, credentials or tunnels is missing.
