Part 2 of AI in the Development Workflow. Last updated 21 Sep 2026.

Goal of this page: one command turns a Jira key into issues/ABE-xxxx.md — a local task file holding everything the ticket knows, structured so both the developer and the agent work from the same brief for the rest of the ticket's life.

1. Why a file, not a chat

  • Context survives. Long sessions get compacted; a file on disk does not. Tomorrow's session starts with read issues/ABE-5457.md and is fully caught up.
  • It is reviewable. You read the brief the agent will work from before it starts coding, and fix misunderstandings at the cheapest moment.
  • It accumulates. Analysis, decisions, verification evidence and deployment notes are appended to the same file (see Parts 3–5). By release time it is the draft of the Confluence release page.
  • It is shareable. A colleague picking up the ticket gets the file, not a chat transcript.

2. The command

Claude Code slash commands are Markdown files in .claude/commands/ (project — we keep them at the workspace root that holds all the ABE repos, so one copy serves ABMB, ABVB, ABF and ABCB) or ~/.claude/commands/ (personal). /task-fetch is one such file; the agent reads it and follows the steps with $1 replaced by what you typed.

/task-fetch ABE-5457
/task-fetch https://internationalsos.atlassian.net/browse/ABE-5457

2.1 Command definition (.claude/commands/task-fetch.md)

---
description: Fetch a Jira ticket and create a task file in issues/
argument-hint: <jira-url-or-key>
---

Fetch the Jira ticket referenced by $1 and create a task file in `issues/`.

## Step 1 — Parse input
`$1` is a key (`ABE-5457`) or a browse URL. Extract the key.

## Step 2 — Fetch via the Atlassian MCP (server `atlassian-isos`)
1. `getJiraIssue` for the key. Keep: summary, description, status, priority,
   issue type, labels, components, fixVersions, assignee, reporter, parent,
   sub-tasks, issue links (with direction and link type), created/updated.
2. `getJiraIssueRemoteIssueLinks` — Confluence pages and external links.
3. Comments: read all of them; keep author, date, body. Quote them verbatim
   under Notes — do not summarise away a BA decision.
4. For every linked or parent issue, `getJiraIssue` again for summary + status
   only (one level deep, no recursion).
5. If the MCP is not available, stop and tell the user to run `/mcp`.

## Step 3 — Write `issues/<KEY>.md`
If the file exists, ask before overwriting; offer `-v2`.
Use the template below. Preserve the description as Markdown, including
tables and checkbox lists. Attachment names go under Notes with a reminder
to download them into `issues/` (the MCP cannot fetch binaries).

## Step 4 — Confirm and stop
Print the path, a one-line summary, and the next step:
`/task-analyse issues/<KEY>.md`. Do NOT start analysing or coding.

3. Worked example — ABE-5457

The ticket said, in full: "Provider 2-0938 Asia Lue Garage is not shown when the agent selects Auto mode. Manual mode shows it. Provider is active in the Benefit system." One screenshot was attached.

/task-fetch ABE-5457 produced a file whose useful parts were not the description but the surroundings the agent pulled in:

Pulled fromWhat it addedWhy it mattered later
Issue linksrelates to ABE-5319 — "Provider edit page shows CMS values"Explained why the UI showed Mobile Provider ticked while the DB said 0 — the screen overlays CMS data
CommentsBA note that the provider "was migrated from the CMS in July"Pointed at the sync path, not the dispatch UI
Remote linksRelease Note v21.01Confirmed the Ver2 sync had shipped in the last release
Attachment nameauto-mode-empty.pngDownloaded manually; showed the exact autocomplete field → AutofillController.ProviderName

Without the fetch step the natural first move would have been to debug the autocomplete. With it, the analysis (Part 3) went straight to the sync and found that isProviderMobile is never written by the Ver2 sync — and that 317 providers share the problem.

4. Rules for the fetch step

  • Fetch only. No code reading, no hypotheses, no fixes. The value of the step is a clean brief; mixing in analysis makes the file unreadable and the agent over-eager.
  • Verbatim over summary for BA comments and acceptance criteria. Summaries drop the one word that mattered.
  • Mark inference. Anything the agent had to infer (goal, requirements from prose) is tagged (inferred) so the reader knows what to challenge.
  • One level of links. Parent and directly linked issues, summary + status only. Recursing through the whole epic burns context for nothing.
  • Never overwrite silently. A task file with a filled Analysis section is worth more than a fresh fetch. Re-fetch into -v2 and diff if the ticket changed.
  • Review before the next step. Open the file, fix the Goal line if the agent misread the ticket, add what you know that Jira does not. Two minutes here saves an hour later.

5. Variations

SituationHow to handle it
Ticket has many sub-tasksFetch the parent once; sub-tasks are listed with status. Fetch a sub-task individually when you pick it up — its file notes Parent: ABE-xxxx so the branch/PR logic in Part 5 stacks onto the parent branch.
Ticket is an umbrella bug list ("net10 Android issues")Keep one file; number the issues in Requirements; each gets its own Analysis sub-heading and its own commit.
No ticket yet (incident, ad-hoc request)Write the file by hand from the template with Jira: —. Create the ticket afterwards and back-fill the key; the file name can be the incident date.
Ticket only says "see attached spec"Fetch pulls the remote link; the agent reads the Confluence page with getConfluencePage and quotes the requirement sections into Context.
Non-English or mixed-language ticketKeep the original under Context; add an English Goal and Requirements. Do not translate the BA's comments.

6. Where the files live

We keep task files in an issues/ folder at the workspace root (outside any single repo, because an ABE ticket usually spans ABMB + ABVB + ABF). They are not committed to the product repos. Once a ticket ships, the file's Analysis and Verification sections are what we paste into the Confluence release page — so nothing is lost when the folder is eventually cleaned up.
