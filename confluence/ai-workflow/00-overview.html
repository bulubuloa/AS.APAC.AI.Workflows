Entry page for a series on using an AI coding agent (Claude Code) as a working member of the APAC Aspire Digital team. Each step of the delivery workflow gets its own page, written from what we actually run day to day on the RSA / Benefit / Vendor projects — not from vendor marketing.

Last updated September 21, 2026 · Owner: Hoang Quach · Status: Living document

Why this series exists

An AI agent is only useful when it has the same context a developer has: the ticket, the code, the database, the CMS, the logs, the deployment pipeline. Given that context it can fetch a ticket, trace a bug across four repositories, verify a hypothesis against UAT data, write the fix, drive a browser to test it and draft the release note. Without that context it guesses — confidently.

The series documents how we give the agent that context and how we keep it on a leash: what it may read on its own, what it must ask before doing, and how we check its work.

Ground rules

  • The agent acts as you. Every MCP call is made with your OAuth token, every commit with your git identity. Nothing it does is anonymous, so review what it writes before it leaves your machine.

  • Read freely, write with permission. Reading Jira, Confluence, code and SELECT-ing from a database is auto-allowed. Comments, transitions, page updates, INSERT/UPDATE, pushes and deployments are permission-prompted every time.

  • Files over chat. Anything worth keeping — the task file, the analysis, the verification evidence — is written to disk (and later to Confluence), never left in the conversation window. Conversations get compacted; files do not.

  • Cite, don't assert. Claims about code carry file:line; claims about data carry the query and the row count; figures are tagged [measured] or [assumption].

  • The BA/QA still decides. The agent surfaces options and blast radius; it does not decide business rules (e.g. whether 317 providers get back-filled). Those go to the ticket as a question.

  • Knowledge is versioned. Instructions, commands, permissions, access recipes and the agent's memory notes live in the ai-workspace repo (Part 0); a session that learns something commits it, so any developer can take over any project.
