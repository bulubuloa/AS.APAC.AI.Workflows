# ABE-5457 — Provider not returned in Auto mode + full audit: "always fetch provider from CMS"

Verified 2026-09-16 against RSA **prod** (`BKKRsa`, read-only SELECTs) and Kontent **prod** env `994226e6` (public Delivery API). Code = `roadside-release-production` (`c65a74d1`). Every project in `BkkIsos47.sln` was swept: BkkRsa, BkkRsa.Core, BkkRsa.Web, BkkRsa.Report, BkkRsaPartner, BkkRsaProvider, BkkRsaCompass, BkkRsaNissan, WebHookBenefitt, BenefitCallBack, MobileConnect.

## 1. The bug (ABE-5457)

| | Value |
|---|---|
| Provider | `2-0938` Asia Lue Garage, `vendorCmsId 3c22b305-85df-42d9-a8a4-044806585897` |
| RSA row | `active=1`, `isDelete=0`, **`isProviderMobile=0`**, `StatusSysnData='Update From Benefit'`, countryCode `(+66)` |
| CMS | status `active`, roadside module `rsa_asia_lue_garage__migrated_`, **`mobile_vendor = yes`** |
| Job | `26JB067586`, `tstampMethod='A'`, clientId 393, TOWING, `accountId` still NULL |
| History | never assigned a job in any mode — not a regression for this vendor |

**Root cause.** `AutofillController.ProviderName` (`BkkRsa/Api/AutofillController.cs:83`) adds `ua.isProviderMobile == true` when `timeStampMode == "A"`. Both lookup paths — RSA name match (`:87`) and CMS-name → `vendorCmsId` (`:101`) — go through that `baseQuery`, so the CMS's own `mobile_vendor=yes` never rescues the row. The live Ver2 sync `ProviderSyncBenefitController.ProviderSyncDataVer2` (`:494-570`) writes dispName/userName/mobile/active/group/note but **never `isProviderMobile`** (only the legacy v1 `MapUserAccount` `:743` does). ABVB `ProviderRoadsideVer2` and `VendorRequestVer2` carry no mobile field at all (`VendorServerless.Shared/Requests/ProviderRoadside.cs:27-42`) — the flag exists only in the Kontent module. The provider edit page overlays the CMS value (`Api/AccountController.cs:296`, ABE-5319), so the screen shows "Mobile Provider" ticked while the column says 0.

**Blast radius (prod).** 783 CMS-linked RSA providers; **317** are CMS `mobile=yes` + active on both sides but RSA `isProviderMobile` 0/NULL (274 `StatusSysnData='Success'` = migrated, 40 `Update From Benefit`, 3 `Create From Benefit`). All 317 are invisible to Auto-mode dispatch today. **Caveat:** CMS has `mobile_vendor=yes` on 687/752 roadside vendors including *BMW Call Center*, *Toyota Call Center*, *Nissan Call Center*, *Benz Star Assist*, *International SOS Thailand* — a migration default, not a business decision. BA must confirm before any backfill.

## 4. Cross-cutting impact of "always CMS, no fallback"

1. **Cannot be CMS-only:** A1–A3 (credentials), A4 (per-request `active` gate), B2/B3/B6 (Auto-dispatch SQL), C3 (`BenefitVendorId`), C6 (SignalR board), D4 (grades), H (FKs). The realistic target is **"CMS master, RSA cache"**: every attribute still lands in `cloud.UserAccount` on sync; reads may prefer CMS.
2. **Vendor-filter loss:** `GetListProvidersAsync` only accepts `Auto Services` + `Roadside Assistance`. 5 active towing vendors + APAC Dev Team fall out. Widen to `Auto Services/*` or re-categorise in CMS before any CMS-gated read.
3. **Published-only:** Delivery returns published variants. Un-publish/draft = vendor vanishes from B1, C1, C4, D1, D5 immediately, including on open jobs.
4. **Data quality flips:** `isProviderMobile` for 317 rows (fixes ABE-5457, but also flags call-centre vendors as mobile); `active` follows `vendor_status`.
5. **Environment mismatch:** SIT/preprod resolve to the prod Kontent env → empty provider lists everywhere CMS gates. Set `KontentEnvironmentId` per site first.
6. **Performance:** no cache; one list = ~12 s; B1 already does it per keystroke; C8/D1/D5/F1 per page. A `MemoryCache` (60 s) + Kontent webhook invalidation, or Delivery `items-feed`, is a prerequisite.
7. **Availability:** every read today has a try/catch → RSA. Without it a Kontent 429/outage = no dispatch (B1), blank names (C1/C4/C8), empty lists (D1/D5), failed reports (F1). `ProviderDetailCMS` returns `null` on error (`BenefitCmsService.cs:429-436`) → silent blanks, not error banners.
8. **Search semantics:** CMS `vendor_name` only; RSA `userName`/legacy `dispName` (suffixed, Thai) stop matching in B1, C2, A5, D1.
9. **Two write paths to kill or redirect:** A7 `AccInfo` POST and E1/E2 sync both write `cloud.UserAccount`; with CMS master only the sync may write.

---

## 5. Recommendation

**Now (ABE-5457, independent of the CMS decision):**
1. `ProviderSyncDataVer2`: pull `mobile_vendor` + `countryCode` (+ `email`) via `ProviderDetailCMS(vendorCmsId)` and write `isProviderMobile`/`countryCode` on create and update — same shape as `NoteFromCmsAsync`.
2. `AutofillController` path (b): rows resolved from the CMS list (already `IsProviderMobile`-filtered) skip the RSA `isProviderMobile` check.
3. Backfill the 317 rows from the CMS **after** BA rules on the call-centre `mobile_vendor` values.

**If CMS-first is still wanted:** "CMS master, RSA cache" — keep the sync writing every attribute (adds `isProviderMobile`, `countryCode`, `email` to Ver2), add a Kontent webhook → re-pull so the cache can't drift, add a server-side list cache, widen the roadside filter, set `KontentEnvironmentId` on SIT/preprod, remove/redirect the `AccInfo` write, and **keep** the DB fallback for reads. Removing the fallback buys nothing once the row is guaranteed fresh and costs availability in B1/C1/C4/C8/D1/F1.
