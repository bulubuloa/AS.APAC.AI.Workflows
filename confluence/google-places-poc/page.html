4. CMS structure fit

  • Fits: vendor → location linked items (multi-branch works); address, coordinates, 7 per-day hours, country (ISO code), price rating ($–$$$$) map 1:1.
  • Gaps: no google_place_id; phone/website only at vendor level (not per branch); cuisine/ambience need a Google-type → CMS-item mapping; Google sometimes returns Thai-script address parts.
  • CMS list bugs found: cuisine items american__copy_ = "Korean", chinese__copy_ = "Mexican", indian__copy_ = "French".

Per restaurant: 1 Text Search + 1 Place Details (+1 Text Search on retry) + up to 4 photos. Example (Savelberg, PROD): textQuery = "Savelberg, Oriental Residence Bangkok 110 Wireless Road. Lumpini. Pathumwan Bangkok 10330, Thailand", regionCode = "TH". Only name, address/city, country and optionally coordinates are sent to Google — no customer data.

7. Cost (to confirm on the Google pricing page)

Live = about one Place Details call per restaurant page view (+ photos). Phone, website, hours and rating are top-tier (Enterprise) fields. Keep the field mask to what the page shows, lazy-load photos, set a daily quota, and estimate monthly restaurant page views before launch.
